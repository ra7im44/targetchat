TargetChat Technical Specification & Architecture

This document serves as the absolute technical reference for TargetChat. It details the underlying systems, deep architectural patterns, database schemas, and networking implementations that run the platform.

1. System Architecture Overview

TargetChat operates on a decoupled multi-tier architecture. It separates the presentation layer (Next.js) from the business logic layer (Express.js), communicating exclusively over REST APIs for persistent actions and secure WebSockets (Socket.io) for real-time streaming.

2. Frontend State Management & Architecture

The Next.js frontend avoids heavy flux architectures (like Redux) in favor of lightweight, decoupled context providers wrapped around the application in _app.js.

  • AuthContext: Fetches /api/auth/me via Axios on initial load. Holds global state for user payload and isAuthenticated status. Handles JWT injection via Axios interceptors for outbound requests.
  • WorkspaceContext: Retrieves the lists of workspaces a user belongs to. Maintains the activeWorkspaceId bridging the dashboard UI and API params seamlessly so users don't have to pick a workspace for every request.
  • GlobalConfig: Fetches /api/system/settings globally to inject dynamic logo, maintenance mode screen, or primary brand color mapped directly onto Tailwind classes holding style={{ '--color-primary': brandColor }}.
  • SWR Data Fetching: Uses Vercel's SWR (Stale-While-Revalidate) algorithm instead of raw useEffect for fetching datasets (e.g., DataTables for Users or EmailLogs). This prevents flickering, caches API responses tightly, and automatically re-fetches on window focus.

3. Security & Vulnerability Mitigation

The backend actively guards against OWASP top 10 vulnerabilities:

  • CORS Strategy: cors({ origin: process.env.FRONTEND_URL, credentials: true }) strictly drops unverified origin pre-flights, except for specifically the /api/widget boundary.
  • Brute Force & Rate Limiting: express-rate-limit is placed on auth endpoints to prevent credential stuffing (e.g., max 5 attempts per IP per 15 mins on /api/auth/login).
  • Data Sanitization (XSS & Injection): Chat messages pass through a text sanitizer before mapping to the LLM or DB. Sequelize natively guards against SQL injection via parameterized queries.
  • JWT Storage: Tokens are configured to securely pass in local storage / session storage with expiry buffers verified rigorously in the Backend's requireAuth.

4. Deep Technical Implementations

4.1 Identity & Access Management (RBAC)

Authentication relies on stateless JWTs. When a user logs in, the backend signs a payload containing { id, role } using HS256.

  • Auth Middleware (requireAuth): Intercepts Authorization: Bearer <token>. Extracts token, verifies via jsonwebtoken.verify. On failure, throws 401 Unauthorized. Attaches the decoded user to req.user.
  • Role Middleware (requireRole('admin')): Verifies req.user.role === 'admin'. Rejects with 403 Forbidden if insufficient.
  • Workspace Context (requireWorkspaceAccess): Queries WorkspaceMember to confirm req.user.id has an active relationship with req.params.id. It sets req.workspaceRole for downstream controllers to allow/block destructive actions.

4.2 Real-time Chat Engine & Central AI Pipeline

This is the core nervous system of TargetChat, engineered for lowest-latency token streaming.

  • Handshake & Rooms: The client connects via io(url, { auth: { token: jwt } }). Unauthenticated sockets drop immediately. Clients emit join_workspace to isolate WebSockets to specific workspace_<id> rooms.
  • Context Window Management: When a user emits send_message, the Node server queries the last 15 messages from the Messages table (filtering out system logs). It transforms these into the standardized [{ role: 'system', content: '...' }, { role: 'user', content: '...' }] schema format.
  • Dynamic Payload Execution: The payload determines whether to fire towards OpenAI or a localized Ollama instance based on the Workspace settings or the underlying Persona settings.
  • Stream Emitting:
    1. The AI Service opens a Node data stream.
    2. The server intercepts data chunks and emits ai_chunk events towards the socket client directly.
    3. The React frontend calculates the diff and concatenates the chunks locally for the visual "typing" feel.
    4. Upon stream end, the backend compiles the full string and inserts the finalized Assistant message into the Database alongside a calculated Token Usage integer.

4.3 Background Jobs & Email Queueing

To prevent blocking the Node.js event pool, TargetChat delegates heavy IO overhead using Bull Queue + Redis.

// Queue Instantiation
const emailQueue = new Bull('email-queue', { 
    redis: { port: process.env.REDIS_PORT, host: process.env.REDIS_HOST } 
});

// Job processing (Worker)
emailQueue.process(async (job, done) => {
    const { to, subject, htmlBody, logId } = job.data;
    try {
        await transporter.sendMail({ from, to, subject, html: htmlBody });
        await updateEmailLog(logId, 'delivered');
        done();
    } catch (err) {
        await updateEmailLog(logId, 'failed', err.message);
        done(new Error('SMTP failure'));
    }
});

4.4 Billing Synchronization & Webhooks

Billing state acts defensively; it only updates by parsing incoming webhooks from Payment Providers. This ensures 100% data integrity against manual database modifications.

  • Validation: Endpoint POST /api/webhooks/stripe triggers stripe.webhooks.constructEvent() passing the Express raw body and the validation signature STRIPE_WEBHOOK_SECRET.
  • Events Handled:
    • checkout.session.completed: Creates or reinstates a Subscriptions DB row. Binds stripe_customer_id to the Users table.
    • invoice.payment_succeeded: Parses the unix timestamp of the invoice end date and overrides current_period_end in the local DB.
    • customer.subscription.deleted: Hard flags the Subscription table as canceled, propagating restrictions throughout the UI via the feature flags sync logic.

5. Feature Capabilities & Entitlement Engine

To restrict users to their plan limits (e.g. Free vs Pro tier limits on AI Models or Members), the core logic evaluates the Subscription_Plans.features JSON column.

  • When navigating to the Dashboard, the frontend matches the User's active subscription ID to the cached Plan object.
  • It evaluates constraints like features.enable_custom_personas or features.max_workspaces. When creating a workspace, the Backend queries this JSON and throws a 402 Payment Required if the constraint limit is breached.

6. Database Schema Specifications

Relationships are handled heavily via Sequelize ORM hooks.

7. Widget Embed Architecture

TargetChat can be embedded directly onto foreign DOMs. The backend serves a vanilla payload (/api/widget/script.js?wk=<workspace_api_key>).

  • Cross-origin Validation: The core Node server verifies the Referer or Origin header against the permitted list in the Workspace settings. If mismatched, the server returns 403 Forbidden on the Javascript request itself.
  • Iframe Encapsulation: The returned script forcefully injects a seamless, styling-isolated <iframe> onto the client DOM to host the React UI. This acts as an absolute barrier against foreign CSS pollution and cross-site scripting from the parent page.
  • PostMessage Bridge: Events (like clicking the chat bubble or window resize computations) tunnel safely between the parent Window and the iframe via window.postMessage().
  • Session Tracking: The widget creates a localized unique targetchat_guest_id cookie/storage entry to bind historical conversations without requiring the end-user to authenticate across tabs.

8. DevOps & Production Deployment Strategy

The system is meant to be resilient across highly concurrent environments like Ubuntu 24.x LTS VPS instances.

Ecosystem.config.js (PM2 Workflow)

In production without Docker, PM2 is the absolute standard. The ecosystem file defines memory constraints and clustering for Express, allowing zero-downtime reloads.

module.exports = {
  apps: [
    {
      name: 'targetchat-backend',
      script: 'server.js',
      instances: 'max', // Leverages Node's Cluster module across server cores
      exec_mode: 'cluster',
      env_production: { NODE_ENV: 'production' }
    },
    {
      name: 'targetchat-frontend',
      script: 'npm',
      args: 'start',
      env_production: { NODE_ENV: 'production' }
    }
  ]
}

Reverse Proxy & SSL Matrix (Nginx)

Node.js shouldn't handle bare socket HTTP connections natively. Nginx must sit in front acting as an edge reverse proxy mitigating Slowloris and DDoS vectoring before traffic touches Express.

  • WebSocket Forwarding: Nginx blocks the Upgrade header by default. The config strictly implements proxy_set_header Upgrade $http_upgrade; and proxy_set_header Connection "upgrade"; explicitly on the socket namespace to ensure WebSockets bridge optimally over TLS (WSS).
  • Internal Security Segregation: Services like Redis (6379) and MySQL (3306) bind aggressively to 127.0.0.1 instead of 0.0.0.0, allowing them to remain firewalled inherently from exterior network polling.
